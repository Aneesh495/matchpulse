# Evidence format

An engineering bundle contains source hashes and full trusted Git identity in `SOURCE_INPUTS.json`, mode and dataset counts in `DATASETS.json`, runtime and storage in `ENVIRONMENT.json` and `RESOURCES.json`, actual command invocation in `COMMANDS.jsonl`, frozen workload packet, delivery journal, every snapshot, raw per-event processing observations, interleaved fixture measurements, transaction cases and final state. `ACCEPTANCE.json` summarizes the profile and cannot establish its own correctness. `REQUIREMENTS.json` qualifies implemented diagnostics. `MANIFEST.json` covers all other bytes, including the closed replay database.

The independent verifier compares source hashes against trusted Git objects and the actual replay checkout. It independently counts provisional and corrected goals, checks exposure and model identities, recomputes the processing percentile, checks absent upstream freshness, rejects undisclosed fee substitution, and recomputes pass opportunity before any future event. It then invokes the exact saved engine source in a bounded subprocess against frozen inputs and compares complete final state. It never retrains or downloads an alternate model. Frozen probes are tracked at [fixtures/probes.json](../fixtures/probes.json).

Negative controls first verify the unmodified bundle. Each copy is mutated, ordinary hashes are recomputed, and the verifier runs as a subprocess. The harness requires the intended semantic rejection message, not just a nonzero exit. Controls cover forged freshness, undisclosed amount substitution, future action leakage, wrong valuation model, missing execution, replay discrepancy, corruption and trusted source mismatch. Actual arguments, return codes and stderr are retained.

Training artifacts retain exact synthetic input bytes, configuration, three seed identities, model weights, optimizer moments and steps, sampler RNG, initial parameters, loss trajectory and held-out predictions. The training verifier separately implements dense and recurrent forward inference and likelihood calculations. These files demonstrate trained numerical mechanics only. They contain no permission to interpret diagnostics as actual player skill, real fees, calibrated uncertainty or production model readiness.
