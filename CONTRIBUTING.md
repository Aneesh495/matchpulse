# Contributing

Run `make test`, `make docs` and a new diagnostic evidence campaign before submitting a semantic change. Keep data modes and uncertainty explicit. New providers need source-specific rights, stable identities, publication/receipt clocks, normalized fixtures, supported-field masks and a truthful acquisition count. Do not use a public web page as blanket redistribution permission.

Changes to models require frozen splits and feature known-at audits before testing. Preserve failed seeds and subgroups. Model files need exact input identities and a separate inference check. Tests should contain tiny independent expectations, not values produced by the function under test. New events need correction, duplicate, inactive-player, sparse-exposure and restart cases.

Keep prose direct and technical. No em dashes, promotional comparisons or claims about unexecuted campaigns. A lightweight CI pass never certifies the full research profile. Use a new evidence directory for every run and identify the executable source separately from reports.
